### 3.1 createMockFallback 注册表

位置：`alarm-warning-frontend/src/utils/mockMode.js`

1. API函数返回 Promise
2. 如果Promise reject → 注册到 mockRegistry[module] = true

### 4.1 risk_analysis（风险研判表）

```sql
CREATE TABLE IF NOT EXISTS risk_analysis (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    risk_name     VARCHAR(200) NOT NULL,
    risk_level    VARCHAR(20) NOT NULL,          -- 高/中/低
    risk_type     VARCHAR(50) NOT NULL,          -- 燃气/电力/交通等
    location      VARCHAR(300),
    description   TEXT,
    status        VARCHAR(20) DEFAULT 'active',  -- active/archived
```

```sql
CREATE TABLE IF NOT EXISTS hazmat_records (

    create_time    VARCHAR(30) NOT NULL
```

### 4.3 tunnel_records（隧道/管廊记录表）

```sql
CREATE TABLE IF NOT EXISTS tunnel_records (

    gas_level      VARCHAR(20) DEFAULT 'normal', -- normal/warning/alert
    status         VARCHAR(20) DEFAULT 'normal', -- normal/maintenance/offline
    create_time    VARCHAR(30) NOT NULL,
```

### 4.4 asset_costs（资产成本记录表）

```sql
CREATE TABLE IF NOT EXISTS asset_costs (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    asset_name     VARCHAR(200) NOT NULL,
    cost_type      VARCHAR(50) NOT NULL,         -- 采购/维护/折旧/报废
    amount         DECIMAL(15,2) NOT NULL,

    create_time    VARCHAR(30) NOT NULL

CREATE INDEX idx_ac_cost_type ON asset_costs(cost_type);
```

### 4.5 work_orders（工单记录表）

```sql
CREATE TABLE IF NOT EXISTS work_orders (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    title          VARCHAR(300) NOT NULL,
    type           VARCHAR(50) NOT NULL,         -- 维修/巡检/投诉
    priority       VARCHAR(20) DEFAULT 'medium', -- high/medium/low
    status         VARCHAR(20) DEFAULT 'pending',-- pending/processing/done/closed
    assignee       VARCHAR(100),
    create_time    VARCHAR(30) NOT NULL

CREATE INDEX idx_wo_status ON work_orders(status);
```

- **risk_analysis / hazmat_records / tunnel_records / asset_costs**：新建独立模块，按用户指定的简化表结构
- **work_orders**：保留现有 wo_orders 复杂设计（含process/staff/SLA），新增用户需要的字段作为补充

## 九、风险和注意事项

1. **Simulator数据结构迁移**：现有simulator.py使用嵌套dict（如 `_state["plans"][id]["flow_nodes"]`），转为SQLite需用关系表+JOIN。建议逐步迁移而非重写。

2. **tunnel_api实时仿真**：该模块有后台线程每5秒刷新传感器数据。持久化时需考虑：
   - 传感器瞬时值不需要每条都存（可定期快照）
   - 告警记录、管线台账需要立即落库
   - 保留实时仿真能力，同时增加持久化层

3. **数据兼容性**：前端组件可能依赖特定的响应格式（如 `{ data: [...], total: N }`），新增CRUD端点必须遵循相同格式。

4. **Gateway路由已就绪**：`application.yml` 中6个模块的路由都已配置，无需修改Gateway配置。

5. **persistence.database.py 共享**：所有模块共用同一个 SQLite 文件和引擎，需注意并发写入的锁竞争（WAL模式已缓解此问题）。
